# Audiobook Android app: handoff context

Status as of 2026-10-14: **v0.1 done, tested on emulator, user approved ("It's perfect").**
APK: `pdf-to-audio/Audiobook.apk` (release build, signed with the debug key).

## What it is
Personal Android app (sideloaded, not published) that plays audiobooks generated by this project's
PDF→audio pipeline, with read-along text, plus a separate TikTok-style looping video mode.

## How it fits the project
- Pipeline (project root, skill `.claude/skills/pdf-to-audio/`): `chunk.py` (PDF → chapter .txt) →
  `tts.py` (Kokoro TTS → `NN_<chapter>.mp3` + `.vtt` sentence timings + `.html` read-along).
- The app reads **only `.mp3` + `.vtt`** from a `*_chunks` folder the user copies to the phone.
- **Coupling:** the app infers paragraph breaks from VTT gaps (`tts.py` pauses 0.25 s between
  sentences, 0.6 s between paragraphs; threshold 450 ms in `paragraphs()` in `Library.kt`). Change both together.
- Chapter title/number come from the filename (`01_chapter_1_introduction_to_psychology`); book
  name from the folder name minus `_chunks`. Chapter duration = last VTT cue end.
- The voice name is not available to the app (not in mp3/vtt).

## Agreed spec (user decisions)
1. Android only. Native Kotlin + Jetpack Compose + Material3 + Media3.
2. Content via **folder picker** (SAF `OpenDocumentTree`, persisted permission), separate folders for books and videos.
3. Player: **full chapter text, scrolling**, current sentence highlighted, auto-scroll, tap a sentence to seek.
4. Keeps playing with screen locked / in other apps; lock-screen + notification controls.
5. Video mode = **separate player** for local video files: vertical swipe (up next, down previous,
   wraps around), each clip loops with sound, tap = pause. **Video sound must also keep playing when
   locked/backgrounded** (user request after v1).
6. Only one thing plays at a time: opening a video replaces the audiobook queue; the chapter resumes
   from its saved position when reopened. Closing the video feed pauses the clip.

## Code map (`android-app/app/src/main/java/com/zeit2206/audiobook/`)
| File | Role |
|---|---|
| `PlaybackService.kt` | `MediaSessionService` + ExoPlayer (speech attrs, wake lock, noisy-pause, 15/30 s skips). Plays **both audiobooks and videos**. |
| `MainActivity.kt` | MediaController (kept until `onDestroy`), `App()` state + navigation (`Screen` sealed), polling (200 ms visible / 5 s background, saves position), `play()` with pending-open queue. |
| `Library.kt` | Models, `Store` (SharedPreferences: folders, per-chapter position/duration, speed), folder scanning, VTT parser, `paragraphs()`, `cueAt()`, formatters. |
| `LibraryScreen.kt` | Library list, chapter rows with progress, mini player, header/empty state, bottom `NavBar`. |
| `PlayerScreen.kt` | Read-along (`ClickableText` per paragraph, scroll to the sentence's line via `TextLayoutResult`), "Back to current", slider, speed cycle 0.8–2×, ±15/30 s, next chapter. |
| `VideoScreens.kt` | Video grid (thumbnails via `MediaMetadataRetriever`), `VideoPager` (`VerticalPager`, virtual page count for wrap-around, `PlayerView` bound to the MediaController). |
| `Trim.kt` | `detectSilentTail()`: decodes the last 15 s of audio (MediaExtractor + MediaCodec), 50 ms RMS windows, < -50 dB = silence; tail ≥ 1 s → end = last sound − 50 ms. |
| `Diag.kt` | `AudiobookApp` (Application) + `Diag`: on-device log `files/diagnostics.log` (512 KB cap): start + previous exit reasons (`getHistoricalProcessExitReasons`), crashes, onTrimMemory, play/pause with reason, player errors, 60 s memory heartbeat while playing, scan timing/permissions. "Report" chip on Videos shares it. Pull on PC: `adb shell run-as com.zeit2206.audiobook cat files/diagnostics.log`. |
| `Theme.kt` | Palette, Literata, SVG-path icons. |
| `res/layout/video_player.xml` | PlayerView: `texture_view` (required inside a pager), `resize_mode=fit`, transparent shutter. |

## Build & test
- `cd android-app && ./gradlew assembleDebug` (or `assembleRelease`, then copy to `../Audiobook.apk`).
- Toolchain: Gradle 8.6, AGP 8.3.1, Kotlin 1.9.22, Compose BOM 2024.02.00 (compiler 1.5.8), Media3 1.3.1,
  compileSdk/targetSdk 35, minSdk 26. **Java 21 pinned** in `gradle.properties` (Android Studio's Java 25 breaks Gradle 8.6).
- Emulator: AVD `Medium_Phone` (1080×2400, Android 16). Helper: `~/.claude/skills/android-app/scripts/adb.sh`
  (`shot`, `tap`, `ui`). On the emulator: `/sdcard/Audiobooks/Psychology2e_WEB_chunks/` (ch. 1) and
  `/sdcard/Movies/Loops/` (3 generated test clips from `samples/test_videos/`).
- Verified: library scan, resume position, read-along highlight + scroll, tap-to-seek accuracy, speed,
  audio + video playback while locked and on home screen, media notification, swipe both ways with
  wrap, tap-pause, close, audiobook resume after videos, release APK smoke test.

## v0.2 (2026-10-15) video fixes
- Videos fit (full width, keep aspect) instead of zoom-crop; no names over playing videos (grid keeps them).
- Swipe glitch fixed: thumbnail (frame 0) always drawn under the video; PlayerView attaches only after the
  player reports the new item (`playingId`), else the new surface shows the old clip's last frame.
- Test clip `samples/test_videos/clip_04_wide.mp4` (16:9).
- Long press = 2× while held (`detectTapGestures` onLongPress/onPress release; badge "2× speed").
- Silent-ending cut (TikTok outro): analysed once per video on scan, single-threaded, cached as `trim2_<uri>`
  in prefs; applied via Media3 `ClippingConfiguration.setEndPositionMs` (files untouched); toggle `trim_on`.
  The outro image starts exactly when the sound stops, so never pad after the last sound.
  Test file: `test-video-from-tiktok.mp4` (sound ends 8.93 s, cut 8.89 s).
- Video view shape comes from the thumbnail's aspect ratio (Compose `aspectRatio` + `RESIZE_MODE_FILL`), not the
  player's reported size, which arrives after the first frame and flashed landscape clips full-screen.
- Notification tap opens the app: `setSessionActivity` (PendingIntent, SINGLE_TOP) in `PlaybackService`.
- `Scrubber` in `VideoScreens.kt`: tap/drag the progress bar to seek (28 dp hit area, thumb + time while dragging).

## v0.2 bug: videos vanish after a long locked playback (user has ~250 videos)
Not reproduced (user declined a 250-video emulator test). Likely cause: unbounded thumbnail HashMap (~0.9 MB per
bitmap) → app killed in background → playback stops; on restart the slow DocumentFile scan showed the empty
"Choose folder" state, so re-picking only *looked* like the fix. Fixes: LruCache (1/8 heap) + RGB_565 thumbs,
one-query folder listing (`listDocs` via DocumentsContract, same URIs), "Loading…" state while saved folders scan.
If it recurs: ask the user for the Report text and check `[exit]` reason, `[memory]` lines, `[scan]` permissions.

## Known limits / ideas not done
- Not tested on a real phone (headphones, battery, real TikTok clips).
- Debug-key signing; fine for sideloading only.
- Loop counter only counts while the video screen is composed.
- Possible next steps: show voice name (would need metadata from `tts.py`), sleep timer, bookmarks,
  per-book speed, M4B support with embedded chapters.
